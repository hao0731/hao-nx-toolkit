# 0.2.0 — release notes

Status: prepared; npm publication and registry verification pending.

Both `@hao-nx-toolkit/golang` and `@hao-nx-toolkit/project-boundary` share version `0.2.0` and declare Nx `^23.2.0` (stable `>=23.2.0 <24.0.0`). This release includes [PR #8](https://github.com/hao0731/hao-nx-toolkit/pull/8). Golang generator behavior is unchanged; its version advances with the fixed toolkit release group.

## Project Boundary

- Register the plugin once in root `nx.json.plugins`; matching projects automatically receive `check-boundaries` without per-project target writes or rerunning init for new projects.
- Discover `project.json` and actual package-manager workspace packages by default. Extend discovery with root `projectMarkers` globs, such as `**/go.mod`, aligned with other plugins' project roots.
- Preserve native affected selection, direct outgoing dependency checks, full graph tags, policy inputs, and parallel report names.
- Validate coverage during init and `check-boundaries-all` only. Uncovered projects do not block ordinary Nx graph, build, or affected commands.
- Preserve normal Nx override precedence and keep the root full-check target addressable when package and project names collide.

## Breaking change and adoption

No legacy migration or target cleanup is provided. Remove obsolete boundary target declarations manually when adopting inference; existing authored targets can override the new inferred defaults. Configure extra markers before rerunning init if it reports uncovered projects. Include `check-boundaries-all` in CI because affected execution can skip uncovered projects.

See the [plugin README](../../packages/project-boundary/README.md) and [ADR 0003](../adr/0003-root-inferred-project-boundary-targets.md) for configuration and trade-offs.

## Validation and publication

Both packed-package suites passed on Nx 23.2.0, 23.2.1, and 23.3.0. Unit tests, builds, lint, typechecking, formatting, package inventory inspection, and dry-run publication passed. The audited tarballs include all registered implementations, schemas, templates, and MIT licenses. Publication status and artifact integrity evidence will be recorded after registry verification completes.
