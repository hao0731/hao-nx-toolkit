# 0.1.0 — draft release notes

Status: planned and unreleased. These notes do not indicate an npm publication or a release date. Both package manifests remain at `0.0.1` until an operator prepares the release.

The first public release is planned to include the following packages, sharing toolkit version `0.1.0` and declaring **Nx `^23.2.0`** (stable `>=23.2.0 <24.0.0`; prereleases excluded). Installed-package tests have passed on **23.2.0, 23.2.1, and 23.3.0** for both plugins; other versions in the range have not yet been verified.

## @hao-nx-toolkit/golang

- Model, Config, Service, Repository, and Handler generators for existing workspace directories.
- Framework-free, Gin, and Echo v5 Handler templates.
- Workspace-relative paths, Go identifier and package validation, and refusal to overwrite existing files.
- Real CLI installation tests plus Go compilation, formatting, and constructor behavior checks for generated templates.

Generated files are skeletons. Application behavior, config loading, framework dependencies, and Go module setup remain the consumer's responsibility. See the [plugin README](../../packages/golang/README.md).

## @hao-nx-toolkit/project-boundary

- An initializer for shared boundary rules and Nx workspace-wide and per-project check targets.
- Direct project dependency checks using tag constraints, with exact, wildcard, glob, and regular expression selectors.
- Native `nx affected` integration and optional JSON reports, including distinct files for parallel project checks.
- Standalone operation without Nx Conformance or an Enterprise license.
- Target-default integration isolated through `@nx/devkit/internal`, replacing deep Nx source imports. This is still an internal API dependency; per-version installed-package tests guard known compatible Nx versions.

Checks cover direct static, dynamic, and implicit project dependencies. Transitive checks, cycle detection, and tag cardinality validation are outside this release's scope. See the [plugin README](../../packages/project-boundary/README.md).

## Packaging and release preparation

Both packages include MIT licensing, npm metadata, public registry settings, and npm-readable documentation links. Only these two plugins belong to the fixed Nx release group; the repository root and E2E projects are not released.

CI runs both installed-package suites on every pull request and main-branch push across the three verified versions, with strict peer installation and actual Nx runtime resolution checks. Repository development and builds, including the pinned `@nx/devkit` dependency, remain on the 23.2.0 baseline.

At release time, Nx generates the root `CHANGELOG.md` from Git history. Review that generated changelog against this draft before publishing, and use these notes as the basis for the GitHub Release. Follow the [release guide](../releasing.md).
